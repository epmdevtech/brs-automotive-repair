# Contribuindo com o Universal SDD

Obrigado por contribuir. O projeto está em desenvolvimento ativo e mudanças no
framework afetam todos os projetos que o adotam.

## Antes de começar

1. Consulte `ROADMAP.md` e as issues existentes.
2. Abra uma issue para discutir mudanças de comportamento, governança ou estrutura.
3. Para mudanças arquiteturais, proponha um ADR baseado em `templates/adr.md`.
4. Mantenha a contribuição focada em um problema verificável.

## Fluxo da contribuição

1. Crie ou atualize uma SPEC quando a mudança alterar comportamento do framework.
2. Registre escopo, não escopo e critérios de aceitação.
3. Obtenha aprovação humana antes da implementação.
4. Faça a menor mudança coerente com a SPEC.
5. Atualize documentos, templates e links afetados.
6. Execute as validações disponíveis e registre limitações.
7. Abra um pull request com motivação, impacto, evidências e riscos.

Correções editoriais pequenas podem usar uma descrição equivalente à SPEC no
próprio pull request, desde que não alterem uma regra normativa.

## Critérios para pull requests

- Não introduzir instruções incompatíveis entre documentos.
- Usar caminhos relativos e links verificáveis.
- Separar regras universais de exemplos específicos de tecnologia.
- Marcar exemplos, recomendações e requisitos normativos de forma inequívoca.
- Não incluir dados sensíveis ou material sem licença compatível.
- Atualizar `CHANGELOG.md` quando houver mudança relevante para consumidores.

## Relato de problemas

Inclua comportamento atual, comportamento esperado, documentos afetados,
impacto e uma proposta de validação. Vulnerabilidades não devem ser divulgadas
publicamente antes de existir um canal de segurança documentado pelo projeto.
