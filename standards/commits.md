# Commit Standard

## Baseline

Commits should be focused, reviewable, and safe to revert. A project may adopt a
specific message convention in its profile.

- Use an imperative summary that states the observable intent.
- Reference SPEC, TASK, ADR, or issue identifiers when available.
- Keep formatting-only or generated changes separate when they obscure review.
- Do not include secrets, personal data, temporary artifacts, or misleading authorship.
- Do not rewrite shared history without explicit coordination.
- Preserve contributor attribution and required sign-off policies.

A clean commit history supports auditability but does not replace the SPEC,
review, tests, or changelog.
